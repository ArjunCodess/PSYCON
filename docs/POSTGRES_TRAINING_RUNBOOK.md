# PostgreSQL and supervised training runbook

## Environment and startup

Use PostgreSQL 16 for this cutover. `PSYCON_DATABASE_URL` is mandatory, and `.env` remains ignored. Speech access keys and the pinned Ollama digest are separate settings. Run `run_psycon.py migrate` explicitly; web requests do not create schemas or tables. The canonical schema is `psycon`, so earlier `public.sessions` cannot collide with instrument sessions. Connection and pool acquisition timeouts are bounded, failed transactions roll back, and `/health` returns 503 when PostgreSQL or migrations are unavailable.

The local deployment currently uses its existing database operator credential. `backend/instrument/permissions.sql` supplies separate NOLOGIN web, worker, and trainer permission groups for externally provisioned login roles. Do not place role passwords in source files. Grant the appropriate group to a login, set its explicit database URL for that process, and reserve schema ownership/migration privileges for the operator. PostgreSQL integration tests exercise web intake and corrections, worker generation logging, and trainer permissions. They reject trainer writes to human labels and application-role DDL. Optional PSYCON_WEB_DATABASE_URL, PSYCON_WORKER_DATABASE_URL, and PSYCON_TRAINER_DATABASE_URL select process-specific logins; the operator URL is used only when these are absent. Reapply permissions through the explicit migrate command after restoration.

`run_psycon.py web` and `run_backend.py` serve the canonical workspace at 127.0.0.1:8001. `run_psycon.py worker` consumes speech, interpretation, durable import, and training jobs. `run_psycon.py trainer` independently consumes durable imports and supervised training jobs, so they do not wait behind speech processing. It uses a separate worker-role connection for imports and trainer-role connection for fitting. Docker starts this CPU service alongside the GPU worker. `run_psycon.py train --snapshot ID` queues and fits a frozen snapshot; without a snapshot it processes one queued training job. Legacy physiological and face training helpers are historical experiments, not the canonical training workflow.

## Import and review

Add session participants, optionally link a longitudinal anonymous person, and confirm the speaker association through a named reviewer. Silent and uncertain participants can keep saved answers without receiving another speaker's features. Record participant training consent explicitly; recording consent alone does not authorize fitting. The legacy recordings have undocumented training consent and must remain excluded.

Choose individual or batch CSV/XLSX upload. Files are limited to 10 MiB, 20,000 rows, 150 worksheet columns, and 50 MiB expanded workbook data. Select a worksheet explicitly when there are several. Formulas and macro payloads are rejected. Map unknown columns or ignore them deliberately. An individual file must match the selected participant; a batch maps each file code explicitly. Review all errors and proposed revisions before committing. Commit saves the source and normalized answers atomically, and correction conflicts require a fresh preview. Identical file/options hashes do not create another submission. Direct-entry forms use the same normalization and revision path.

Fields preserve missing, N/O, and 0 separately; reviewer/respondent identity is never inferred from the uploader. Typed metadata retain the actual marksheet definitions. Positive ratings require contextual timestamps for eligibility, K and M–T require event/response context, and Q–T need an earlier same-person same-session baseline. Visual claims remain unsupported. S is currently excluded from training because the instrument's extractor has no supported vocal-change window features. Independent communication targets require repeated human contextual evidence.

Review submissions independently, retain original judgments, and adjudicate conflicting scores explicitly. `/api/instrument/training/readiness` lists target-specific exclusions. `/training/agreement` reports real paired counts and available agreement statistics, separate from construct validity.

## Snapshots, training, and models

Freeze under a serializable transaction. Each manifest records seed, human answer and mapping revisions, source hashes, feature version, units, missingness, role, context, exclusions, and materialized split assignments. Confirmed person links and shared original recordings connect whole sessions for unseen-participant splitting. Connected components cannot span incompatible roles or reference data. Partial imports share original-video hashes. Longitudinal studies use explicit, strictly ordered training/validation/evaluation dates, with source grouping and no random time split.

The initial task minimum is 12 training participant/session examples across three independent recording groups and at least two observed score classes. These are exploratory engineering gates, not evidence of adequate scientific sample size. Fit a training-only median baseline and a regularized multinomial approximation to ordinal labels. Imputation, missing indicators, and scaling fit only on training rows. Regularization selection uses validation data; final test metrics do not select hyperparameters. Each target can refuse independently. The dashboard summarizes frozen per-target record, source-group, and score-class counts before fitting, disables snapshots with no fit-ready target, and polls queued/running jobs without replacing an activation form while it has focus.

Artifacts are portable JSON coefficients with feature order, training-only transformation statistics, version, hash, and database lineage. No pickle execution is required. Run provenance records the actual fitting worker's Python, NumPy, scikit-learn, code revision, and source-module hash separately from the enqueueing process. A retry with a changed fitting runtime fails explicitly; enqueue a new run instead of mixing artifacts from different implementations. Verify the artifact hash and feature schema before loading. A model becomes evaluated only if the prespecified held-out counts and MAE comparison against the median baseline pass in validation and final evaluation. Report MAE, macro-F1, balanced accuracy, confusion matrix, quadratic kappa when defined, Brier score, coverage, and group-bootstrap intervals where enough held-out groups exist. Probabilities remain uncalibrated; no calibrated confidence is claimed. Fitting does not activate a model. Activation and rollback record an operator, reason, previous version, and explicit exploratory acknowledgment where needed.

Predictions are separate records. Event-linked targets abstain without independently reviewed inference context; human target scores never supply that context automatically. B/C LLM packets share supervised versions and predictions, while only C adds historical personalization. Measured reports remain available with no active model or no LLM.

## Backup, restoration, deletion

`run_psycon.py inventory` reads actual database counts and logical-row hashes. The one-time `migrate-source` command opens only the active instrument source read-only and requires a verified source-backup marker. It preserves keys, original citations, nulls, aware times, raw model packets, and source relationships, then verifies every imported column. Replaying does not replace destination conflicts or resurrect records from smoke verification directories.

`run_psycon.py backup --destination PATH` requires a separate directory with room for registered original media and models. It writes a PostgreSQL custom dump and verifies a disposable database restore, copies unique asset hashes with exact filenames, and verifies restored bytes. Pause mutation and workers while taking a coordinated backup. A change during the database dump fails verification. Temporary normalization/model caches are disposable.

Restore with `PSYCON_DATABASE_URL` pointing to a newly provisioned empty database and `run_psycon.py restore --destination BACKUP --local-destination NEW_ROOT`. It refuses existing local roots and application tables, verifies dump/asset hashes, restores the database, compares logical-row counts and hashes, and remaps only registered roots and session paths. It never overwrites active originals.

Withdrawal invalidates dependent datasets, predictions, historical results, and model eligibility. Deletion also removes source answers and model weights and purges affected frozen private copies. Shared batch source bytes are removed when they contain a deleted participant; other normalized answers and their provenance hashes survive. Retirement records explain why weights are unavailable. Deletion tombstones require purging affected backup generations before restoration. The current implementation records this policy but does not automatically erase disconnected external backups.

## Original videos, generated text, and reviewed reanalysis

Run `run_psycon.py register-videos` to verify and register the 11 originals and their retained analysis links idempotently. Registration keeps each exact filename, extension, source hash and local path. It does not manufacture a transcript for failed attribution. The dashboard displays the original full-discussion dataset; reviewed reanalyses are separate session records.

Local interpretation jobs retain their frozen inputs, exact prompt, model digest, decoding settings, raw output and validated speaker-specific claims. Every new generation attempt has an immutable `llm_generation_attempts` record, including retry failures, malformed JSON and truncated output. Partial text is inspectable in the audit export but cannot become a successful report. Migrated attempt 0 records only the retained legacy outcome; earlier retry history was unavailable.

Review source ancestry before training. Independent recordings, excerpts and derived recordings have explicit reviewer records; uncertain or unreviewed ancestry is excluded. Hashes catch exact duplicates, while reviewed source relationships connect excerpts. There is no automatic acoustic near-duplicate detector. Personal baselines and reference aggregates also count independent source groups, so a new analysis cannot become its own earlier baseline.

A reviewed merge/split starts a separate durable reanalysis using the same immutable original. Optional reviewed anonymous speaker intervals replace diarization for that new analysis. Existing citations, answers and speaker mappings remain attached to the old analysis; review the new participant-to-speaker mappings before joining any new labels. Normalization writes under `derived/normalized.wav`, never over an original of that name.

See [dataset protocol](DATASET_PROTOCOL.md) for frozen targets, splits and evaluation rules, and [reproducibility](REPRODUCIBILITY.md) for current test commands.

## Neon and Docker startup

Run `.runtime\venv\Scripts\python.exe run_psycon.py docker` on Windows. The launcher supplies an explicit host-to-container path mapping, builds the thin image over the installed GPU runtime, and starts initialization, web and worker services. Initialization applies immutable migrations and queues a separate analysis of each retained full-video recording once. Repeated startup reuses the same request identity, leaving original evidence untouched. The web service binds only host loopback port 8008; its configured Docker gateway networks supplement the default loopback-only API check, and mutation/Origin protections remain active.

The ignored `.env` selects PostgreSQL explicitly. Neon transaction poolers must not receive startup `search_path` options: schema, timeout and least-privilege role are transaction-local settings on every checkout, including heartbeats and resource cleanup. Prepared statements are disabled for transaction-pooler portability. Native launchers never override the configured URL with a local database. Original filenames and persisted host paths stay unchanged; `PSYCON_PATH_MAP` resolves their registered mounts inside Linux workers.

Remote dumps use a version-compatible PostgreSQL tools image rather than the old local database container. `PSYCON_POSTGRES_TOOLS_IMAGE` selects that image (default PostgreSQL 18). Set `PSYCON_BACKUP_VERIFY_DATABASE_URL` to a disposable administrative PostgreSQL instance of the same or newer major version when the source provider cannot create verification databases. Credentials travel through environment variables. Verification compares every logical table count and row hash before cutover; restore verification does not replace the independent original-media backup requirement.

Docker uses the configured local Ollama model through `host.docker.internal:11434`; start the bundled Windows service with the documented local-runtime command when required. Model absence, service failure and digest mismatch remain explicit errors. Speech processing can complete independently. Human consent, participant mapping and reviewed labels remain required for supervised training; queueing videos does not manufacture annotations or grant consent.

CUDA execution records `transcription_compute_type` explicitly (`int8_float16` by default for this 8 GiB deployment), releases PyTorch's cached model memory between stages, and unloads Whisper weights after success or failure using the documented [CTranslate2 unload API](https://opennmt.net/CTranslate2/python/ctranslate2.models.Whisper.html#ctranslate2.models.Whisper.unload_model). Precision changes require a new input revision and recorded provenance; they do not establish accuracy or experimental equivalence. Synthetic integration fixtures require `PSYCON_TEST_DATABASE_URL` and use CPU substitutes, while real Docker processing exercises CUDA independently.
