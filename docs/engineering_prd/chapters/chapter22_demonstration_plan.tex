\section{Demonstration Plan}
\label{sec:demonstration-plan}

A live demonstration should be prepared, showing:
\begin{itemize}
    \item Device startup.
    \item Sensor initialization.
    \item Live physiological acquisition.
    \item Live audio capture (with consent).
    \item Data synchronization.
    \item Backend visualization.
    \item AI inference output.
    \item Consented wearer enrollment and encrypted-profile deletion.
    \item Anonymous speaker timeline, conservative wearer match, and attributed transcript.
    \item Per-speaker speaking rates, pauses, response gaps, overlaps, interruptions, and conversational jitter estimates with unavailable reasons.
    \item An optional 3--8 second sustained /a/ vowel with a separately displayed controlled Praat jitter result.
    \item Safe shutdown.
\end{itemize}

\begin{requirementbox}
A recorded backup demonstration should also be prepared in case of hardware issues.
\end{requirementbox}

The Week~3 software demonstration uses a consented multilingual recording with at least two speakers, natural pauses, and overlap, plus a separate consenting-wearer sustained /a/ vowel. It must show that missing model access, missing enrollment, ambiguous identity, poor-quality speech, and an inadequate or absent vowel produce explicit abstention states while acoustic analysis and transcription remain independently usable.

The Week 7 runbook fixes a timed physical sequence, roles, preflight, planned communication interruption, export verification, profile deletion, safe shutdown, and a software-only fallback. With one set, the center Audio Module records the circle while the Wrist Module measures one focal wearer; later sessions rotate the wearer. The backup-record template requires consent, revisions, session ID, duration, file hash, storage, redactions, faults, and corrective actions. No live or recorded hardware demonstration has been supplied, so both gates remain open.
